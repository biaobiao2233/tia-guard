# TIA-Guard v0.2.0-alpha.1

本次预览将项目主线调整为 **AI 与工程软件的连接、工程操作和结果验证**。保留 TIA-Guard / tia-guard 名称及既有命令、配置；TIA 工程文本化和 Git 工作流作为附加能力继续提供。

This alpha connects AI agents to engineering applications and their real compile/verification workflows. Existing names and interfaces remain compatible. TIA Git/source workflows remain available as optional features.

## 按软件下载 / Packages

| 文件 | 内容 |
| --- | --- |
| `tia-guard-tia-v0.2.0-alpha.1-windows-x64.zip` | TIA GUI + CLI + self-contained .NET 8 Bridge + isolated net48 Worker |
| `tia-guard-bridge-v0.2.0-alpha.1-windows-x64.zip` | TIA MCP / HTTP 无 GUI 包；已包含在上一个包中 |
| `tia-guard-twincat-v0.2.0-alpha.1-windows-x64.zip` | TwinCAT stdio MCP、锁定的生产 Node 依赖、原生绑定 Worker、本机 interop 生成脚本、文档和示例 |
| `skill.zip` | 可选 TIA Gateway Agent 操作说明 |
| `SHA256SUMS.txt` / `release-manifest.json` | 所有发布 ZIP 的校验值，以及准确源码提交/源码树和资产身份 |

[安装及 MCP 配置 / Setup](../ADAPTER-PACKAGES.md)。安装对应工程软件及官方组件仍是前提。TIA Bridge 自带 .NET 8 运行时；TwinCAT 需要 Node.js ≥22、.NET 8 Windows Desktop Runtime x64、XAE 和本机生成的 interop。包版本不改变现有内部 `0.1.0` 协议标识。

## 本次包含的实现 / Included implementation

- **TIA 从零生成**：受支持的 SCL / manifest → 新 V21 S7-1200 工程 → 实际编译 → 独立回读验证 → 新 `.ap21`；CLI / HTTP / MCP 共用流程。包含完整编译诊断以及英文 Windows 下 Worker 中文输入的 UTF-8 修复。
- **TIA AI 工具**：读取工程上下文、变量/引用/有限 LAD，受控副本 patch、预览/单次授权、编译、回滚和新副本发布；现有 GUI、CLI、工程文本化和 Git 工作流保留。
- **TIA PLCSIM 阶段成果**：原生 UIA/FlaUI 后端、独占虚拟实例生命周期、电源控制、SIM 表地址配置、临时副本硬件/软件编译准备、桌面包身份的 DLL 搜索兼容修复。**实验、默认关闭；完整下载/RUN/扫描/实际 I/O 未通过运行验收，`runtimeQualified=false`。**
- **TwinCAT 独立适配器**：ST 从零工程、实际 XAE 编译错误诊断/修复、保存关闭重开核验；自有 Usermode PLC 软件仿真、RUN/STOP、标量反馈及有效许可复用；一根连续软件 NC/PTP 轴的受限仿真。

TIA 与 TwinCAT 使用各自的官方工程入口，不把 TIA 的工程文本化机制强加到其他软件。TwinCAT 是独立 stdio MCP，不要求运行 TIA Gateway，也尚未进入 TIA GUI / HTTP。

## 未包含及限制 / Exclusions and limits

- **CODESYS PR #64 未合并，不包含。** Doctor/SARIF PR #7 和 advisory AI PR #5 同样未合并。
- TIA 限 V21、CPU1212C/V4.7 及文档列明的对象；现有 GUI/Gateway 修改闭环的 Issue #41 仍有独立复验要求。完整 PLCSIM 运行验证未完成。

- 不包含真实 PLC / EtherCAT / 电机操作、Safety、任意工程全量编辑或跨厂商转换。用户原工程、现有实例、官方许可及系统权限不因安装包而被修改。
- 不分发厂商工程软件、从安装目录取得的私有 DLL、许可证、凭据或用户项目。公开 NuGet / Node 依赖按原许可证分发并保留声明。

建议先在专用目录和自己的测试工程副本中使用。遇到问题请附适配器、包版本、Doctor 结果和已脱敏诊断。
