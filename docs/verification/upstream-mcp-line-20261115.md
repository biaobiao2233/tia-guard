# 受限 MCP 写入与独立产线联调

2026-11-15，固定原版上游 v2.7.11 / TIA V21 / PLCSIM Advanced 本机 Softbus / Factory I/O 2.5.10。本轮只使用新工程副本、新软件 CPU 和新场景副本，保留用户已有博途和仿真管理器。

| 范围 | 真实结果 |
|---|---|
| MCP 写入 | 实际客户端 → 本适配器 → 原版引擎；只接受本机计划固定哈希的单个新 FC；调用者改路径被拒绝 |
| 编译与持久化 | 新函数导入、编译 0 错误、保存关闭重开、NetworkSource 内容一致、再次编译 0 错误；保留 1 个原有硬件 I/O 警告 |
| 错误反例 | 生成仍返回成功的错误 SCL，实际编译报 1 个未定义变量错误；MCP 返回失败及完整的有限编译诊断，未保存失败结果 |
| 云端测试 | 32 个 Node、4 个 Python 测试通过；覆盖固定目标/源码、已有块拒绝、额外声明拒绝、禁止会话提权、编译失败不保存等边界 |

| 单独异常测试 | 真实托盘运动中 Stop、真实反馈源暂停，两项均撤输出并报 1604；计数保持、恢复反馈后 2 秒不自启、带料 Reset 拒绝通过 |
| 最后复位与保存 | 编辑态清空物料经明确确认后，空场景 Reset 成功；场景通过原生保存接口保存。软件 CPU 留 STOP、Factory 留编辑态 |

三箱采集 536 帧，异常测试采集 478 帧；两组采集无错误，线程均退出。所有帧 Factory API 输入写、执行器写、Force 和场景电气故障均为 0。独立反馈 DB 有真实 SDK 反馈写入并计账；反馈暂停是单独故障注入，已恢复，不冒充正常验收或场景传感器强制。

新 MCP 函数没有接入 OB1；下载项目包含该函数，但产线动作仍由已有 C16 控制逻辑执行。这证明新工程候选能编译、持久化和下载，以及既有控制逻辑在该候选中的真实回归；不证明新增函数已控制产线。下载使用现有独立后端，并未透传上游的任意下载能力。

编辑态清场不是正常出库，故障测试中的两次托盘送料不是完整托盘搬运验收。带料装层、满托盘出库与原生触摸屏控制尚未完成，不标整线 PASS。准确源码/回执与采样指纹见[机器摘要](upstream-mcp-line-20261115.json)；原始工程、场景、原生截图、日志和令牌均留本机。

复演顺序：准备固定源码与工程副本计划 → 以新 MCP 会话调用 upstream_program_copy → 绑定新软件 CPU → 核对本机 Softbus 独占归属后完整下载 → 从保存场景新复制并绑定新实例名 → 启动官方驱动和结构化采集 → 三箱/堵塞/Stop/Reset → 单独故障注入并释放。每步重新读取实际结果，禁止复用旧 PID、nonce、旧下载回执或重放已完成请求。
